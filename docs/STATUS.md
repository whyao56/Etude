## 二、做完的

### 核心循环（端到端可用）

- 给一个词/短语/句子 → 判定 `kind` → 生成 8 条**不同上下文**的例句
- 每条例句配 2~3 种**彼此不同**的中文说法
- 逐条合成语音（Edge TTS 或 OpenAI 兼容 TTS），内容寻址缓存
- 铺开**五种通道**的卡片：阅读 / 听力 / 口语 / 打字 / 造句
- 间隔重复调度（简化版 SM-2，「没想起来」走 10 分钟重来）
- 每天的新卡配额 + 到期队列

### 大模型接入

- 7 家预置（DeepSeek / 通义 / 智谱 / Kimi / 豆包 / OpenAI / Ollama）+ 自定义
- 统一走 OpenAI 兼容协议
- 严格 JSON 输出，三层兜底解析
- **错误分诊**：每种失败给一个**能修好的方向**（不是「重试」）

### 语音

- Edge TTS（免密钥、带 7 个英文音色）
- OpenAI 兼容 TTS（`/audio/speech`，6 个音色）
- 内容寻址：同一句话换音色生成新文件、换回来命中旧文件
- **部分失败不算整体失败**：8 条里挂 2 条 → 拿到「6 条能听、2 条补语音」

### 界面

- 单文件 HTML，零构建、零 CDN、零框架
- **断网可练**（例句和语音都在本机）
- 五通道各自的操作方式和评分
- 打字卡逐词比对（红=漏/错、黄=多打、绿=对）
- hash 路由、键盘操作（空格翻面 / 1-4 评分）

### 工程

- `--check` 自检八项，`--check-deep` 真连一次模型
- `%LOCALAPPDATA%\Etude` 数据目录，与程序目录完全分开
- 备份走 `VACUUM INTO`（不是复制文件）
- 端口占用分类处理（对面是自己 → 复用，不是 → 换端口）
- `/api/health` 自述 pid/版本/数据目录
- 打包 + 归档核对 + 冻结态自检 + 端到端 + 发版脚本

### 测试与守卫

- 113 个用例：逻辑、边界、错误方向、路径穿越、隐私红线
- `check_js.py`：前端调用点 + **事件名大小写**（这条抓过真 bug）
- `ui_smoke.js`：真浏览器点一遍 + 收集控制台错误
- `e2e_check.py`：对打包版打真实 HTTP
- **探针自检**：守卫在给结论之前先验自己

## 四、**没验证**的（这一节最重要）

### 4.1 真人长期使用效果 —— 完全没有验证

代码逻辑是**对着理论写的**（六条主张逐条映射，见 THEORY.md），
但「照着练三个月会怎样」**没有任何数据支持**。

具体说，以下全部是**未经证实的假设**：

- 假设一：8 条例句足以让大脑开始归纳出用法。
  **没有任何证据说明 8 这个数字是对的**，它只是一个「一次生成不贵、看起来够多」的折中。
- 假设二：五种通道分开练比合成一张卡更有效。
  理论上是这么说的，但这个产品**没有做过对照实验**。
- 假设三：「没想起来 → 10 分钟后再来」比「推到明天」更有效。
  这是我加的（原文没提间隔重复）。10 分钟这个数字是拍的。
- 假设四：每次随机给一种中文说法能阻止「英文↔固定中文」的锁死。
  合理，但没有验过。
- 假设五：模型生成的例句质量够用。
  **这条最可能不成立** —— 弱模型给的句子平淡甚至不地道，
  而程序不做任何质量校验。

**这一节存在的意义**：如果三个月后发现效果不好，应该能从这里看出
「是哪个假设错了」，而不是笼统地觉得「这个方法不行」。

### 4.2 只在 Windows 上跑过

- 打包和端到端**只在这台 Windows 机器上验证过**。
- 没有在干净的 Windows 虚拟机上装过（本机有各种运行时，
  「我这里能跑」的证明力有限）。
- **没有测过：** 中文用户名下的路径、没有写权限的目录、
  杀毒软件拦截、公司代理/防火墙环境、显示器缩放不是 100%。
- `paths.py` 里给非 Windows 留了兜底（`~/.etude`），
  **但那行代码从没被执行过**。

### 4.3 模型兼容性只测了 7 家中的「协议层」

- 7 家预置的 base_url 和默认模型名是**照着各家文档填的**，
  没有逐个真机验证过（手上只有一部分厂商的密钥）。
- 豆包的模型名要填**接入点 ID**（`ep-xxxx`）而不是模型名 ——
  这一点在 README 和 QUICKSTART 里都标注了，
  但它的报错信息会不会清晰地指出这件事，**没验证**。
- 真正跑通的只有：本地假模型（`openai_stub.py`）+ 端到端测试里的假 HTTP 服务。
  **这两条覆盖的是「协议实现对不对」，不覆盖「各家的实际行为」**。

### 4.4 语音只测了「能用」，没测「好听」

- 音色列表是 Edge TTS 官方文档里的名字，没有逐个听过。
- 语速/音量的 `+x%` 格式是 Edge 的约定，OpenAI 兼容端点**是否接受同样的写法
  没有验证** —— 大概率不接受，需要转换（见「已知问题」）。
- 长句子的合成质量、边缘情况（数字、缩写、专有名词怎么念）没测过。

### 4.5 并发只有 3 个线程

`ThreadPoolExecutor(max_workers=3)`。同时生成超过 3 个训练包时，
第 4 个会排队 —— **界面会显示「正在生成」，但实际还没开始**。
没有做过「一次生成 10 个包」的测试。

### 4.6 数据规模没压过

- 最大的测试数据是 3 个包 / 24 条例句 / 120 张卡。
- **没有测过：** 几百个包时列表页会不会卡、
  上万张卡时队列查询会不会慢、音频目录上万个文件时的表现。
- `idx_cards_due ON cards (due_at, introduced)` 是按预期建的，
  但没有在真实数据量上验证过执行计划。

## 五、已知问题

| 问题 | 影响 | 打算怎么办 |
|---|---|---|
| Edge TTS 依赖在线接口 | 断网时**新生成的包**没有语音（已生成的包不受影响） | 无解，Edge 本来就是这个性质。已经在文档里说清了 |
| **语速/音量设置在大模型 TTS 下不生效** | `_synthesize_openai()` 的 payload 里只有 `model` / `input` / `voice` / `response_format`，**没有 `speed`**。也就是说选了 OpenAI 兼容 TTS 之后，设置里的语速调节是静默失效的 —— 不报错，只是没作用 | 0.0.2 把它映射成 OpenAI 的 `speed`（0.25~4.0 的浮点数，不是 `+10%` 字符串） |
| 大模型 TTS 的音频缓存会被语速设置分叉 | `cache_name()` 把 `rate` 算进哈希，但上一条说明 OpenAI 路径根本不用 `rate`。于是**只改语速就会重新合成一份内容完全相同的文件**，白占磁盘 | 同上的修复顺带解决：OpenAI 路径把它转换后参与哈希 |
| 豆包模型名要填接入点 ID | 填错会得到 404 | 已在文档里标注；考虑在「测试连接」里专门识别这种错 |
| 严格 JSON 输出对弱模型不友好 | 弱模型会给出格式错的回复，或偷懒给逐字翻译的「场景」 | 三层解析兜底 + 错误提示说清方向。**换模型比改代码有效** |
| 一次生成多个包时会排队 | 第 4 个及以后显示「正在生成」但还没开始 | 界面显示「排队中」（现在也是「正在生成」，措辞可以更准） |
| 生成中途关掉程序 | 那个包会停在 `generating` | 下次启动 `recover_stale()` 会标成 `failed`，可以点重生成 |
| 界面文案只有中文 | 英文用户用不了 | 0.0.1 明确面向中文用户 |

## 六、边界情况清单

| 情况 | 状态 |
|---|---|
| 生成时音频合成部分失败 | ✅ 测了。降级为记录，其余可用，界面出「补语音」 |
| 模型返回带围栏的 JSON（` ```json ... ``` `） | ✅ 测了。`extract_json()` 第二层剥围栏 |
| 模型返回带解说词的 JSON | ✅ 测了。第三层遍历每个 `{` 找 |
| 模型返回纯文本 / 空回复 | ✅ 测了。抛错并给方向 |
| 401 / 403 / 404 / 429 / 5xx | ✅ 测了。**各自给不同方向**，有测试断言「互不相同」 |
| 密钥错误 | ✅ 测了 |
| 本机地址连不上（Ollama 没开） | ✅ 测了。专门识别成 `local_service_down` |
| `response_format` 不被支持（400） | ✅ 测了。去掉后重试，**不计入重试次数** |
| 音频路径穿越（`..%2F..%2Fconfig.json`） | ✅ 测了。正则挡在文件系统之前 |
| 密钥回传到界面 | ✅ 测了。断言 `/api/config` 响应里搜不到 |
| 端口被旧进程占用 | ✅ 测了。分类处理 |
| 数据库开着 WAL 时备份 | ✅ 测了。走 `VACUUM INTO` |
| 上次崩在 `generating` | ✅ 测了。`recover_stale()` 标 `failed` |
| 重复的例句 | ✅ 测了。`normalize()` 主动丢弃 |
| 空例句 / 空场景 | ✅ 测了。丢弃，不写库 |
| 中文说法少于 3 种 | ✅ 测了。回退到 `scene_zh` |
| 评分值非法（比如 99） | ✅ 测了。接口拒绝 |
| 磁盘满了 | ❌ **没测** |
| 数据库文件被外部删掉 / 损坏 | ❌ **没测**（自检能发现查不了，但不能修） |
| 同时开两个实例写同一个库 | ⚠️ 部分测了。端口复用能防住「双击两次」，

| 系统时间被改（往前调） | ❌ **没测**。间隔重复会表现异常 |
| 生成 1000 条例句 | ❌ **没测**。提示词会很长，模型可能截断 |

## 七、如果要给一个「能不能用」的结论

**能用**，前提是你接受这三条：

1. **只在这台 Windows 上验证过**，别人的机器上可能碰到没测过的情况；
2. **例句质量取决于你配的模型** —— 程序不做质量校验，
   弱模型会让整套方法退化成中译英；
3. **效果没有验证过** —— 它没有让任何人变成更流利的英语使用者（据我所知）。

它值得一试的地方在于：上面那些「没验证的假设」如果有一条错了，
你会在两三周内感觉到（比如「例句都差不多，练了几次就不想练了」，
那就是假设一错了），而不是三个月后才发现。
