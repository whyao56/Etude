## 二、做完的

### 核心循环（端到端可用）

- 给一个词/短语/句子 → 判定 `kind` → 生成 8 条**不同上下文**的例句
- 每条例句配 2~3 种**彼此不同**的中文说法
- 逐条合成语音（Edge TTS 或 OpenAI 兼容 TTS），内容寻址缓存
- 铺开**五种通道**的卡片：阅读 / 听力 / 口语 / 打字 / 造句
- 间隔重复调度（简化版 SM-2，「没想起来」走 10 分钟重来）
- 每天的新卡配额 + 到期队列

### 配图「检索 + 画图」并行（0.0.3 新增）

- 新来源 `both`，**就是默认值**，排在选项第一位。
- **先到先得**：谁先给出合格的图谁赢。不是「两个都等再择优」——
  检索 1–3 秒、画图 8–25 秒，等两个都到等于把画图的慢加在检索身上。
- 退出时 `shutdown(wait=False)`，**不假装能取消**正在跑的线程。
- `both` 模式下落盘文件名仍用**实际命中的**来源前缀，
  所以缓存能被单源模式直接复用。
- 文生图提示词重写成四段（画面/怎么拍/硬性要求/反面清单），
  明确写「35mm、现场光、中景」。
- 检索词：砍掉破折号后那半截、滤掉心理/言说动词、缩写拆基词。
- 排序把**标题命中数**算进去 —— 这是图库免费给的相关性信号。

### 手动调进度（0.0.3 新增）

- 界面密度两档（简易 / 进阶），`isAdvanced()` 是唯一判断点。
- 逐张改 SRS：间隔（连带算到期时间）、难度（夹 1.3~3.5）、
  打回新卡（同时归零间隔/次数/遗忘次数/上次评分）。
- **暂停**（`cards.suspended`）：不进队列，也不计入「今天到期」。
- **批量**：暂停 / 恢复 / 推后 1 天 / 推后 7 天 / 当作没学过。
  推后从**各自当前**的到期时间往后推，不是统一设成 `now+days`。
- **卡片浏览页**：按训练包 / 通道 / 状态筛选，能搜索，能分页。
- 例句增删改：原文、场景（中英）、语域、中文说法；
  加例句时**五个通道的卡片一起铺**；删例句**手写级联**删卡；
  「补齐卡片」的语义是补缺，不动已有进度。

### 撤销与导航（0.0.3 新增）

- 「上一张」只回看，**不改数据**；「下一张」跳过，**不计入本次已练**。
- 「撤销」把卡退回队列，并**连 `reviews` 那一行一起删**
  （否则新卡配额会被静默吃掉）。
- 撤销靠 `reviews.prev_state` 快照，**不靠公式反推**；
  快照缺失时**拒绝执行**而不是清零。

### 修好的：大模型语音取错音色（0.0.3）

- 音色取法收敛到唯一一处 `tts.resolve_voice(cfg)`，按引擎取，不互相退回。
- `tts.synthesize_cfg(text, cfg)` 承接整段配置，三条路径统一走它。
- **自检从「import 一下就过」改成「真的合成一句」**（`--deep` 时）。

### 场景配图（0.0.2 新增）

- 「场景」这一侧可以带一张图。三条来源：
  - **检索 + 画图并行**（0.0.3 起为默认）：两条路同时开跑，先到先用。
  - **只用开放图库检索**：Openverse 为主、Wikimedia Commons 兜底。
    免费、不需要密钥。
  - **只用文生图**：任意 OpenAI 兼容 `/images/generations`。
    （预置智谱 CogView-3-Flash，它有免费档。）
  - 也可以关掉，只用文字。
- **配图只出现在「场景」这一侧。听力卡上永远没有图** —— 那是方法要求。
- 文件扩展名**只从文件头嗅探**，不信 URL 后缀、也不信 `Content-Type`。
- 按内容寻址命名，同一场景不会重复下载；超过 4 MB 的图拒绝存。

### 以目标为导向的学习计划（0.0.2 新增）

- 三档目标：`fluency`（真的学会）/ `exam`（应付考试）/ `custom`（自己描述）
- **先出大纲，再由用户决定**：`draft` → 勾掉不要的 → `start` 才开工
- 大纲每条带类型（词/固定说法/句型）、使用领域、CEFR band、
  「为什么值得学这一条」
- 考试预设里的 CEFR band **只当范围参考**；提示词里写死
  「一份『重要单词表』是一份失败的大纲」
- 计划的进度和单个训练包的进度分开记
  （作业键从整数 id 改成 `lesson:<id>` / `plan:<id>`）

### 数据目录可搬迁（0.0.2 新增）

- 设置 → 数据：填一个目录就能把整个数据目录搬过去
- **指针文件永远留在平台默认位置**；优先级 `ETUDE_DATA_DIR` > 指针 > 平台默认
- **复制成功才写指针**；旧数据**永远不自动删**；搬完要重启
- 空白路径、搬到自己里面、目标不可写、空间不够 —— 都在动手前拦下

### 大模型接入

- 7 家预置（DeepSeek / 通义 / 智谱 / Kimi / 豆包 / OpenAI / Ollama）+ 自定义
- 统一走 OpenAI 兼容协议
- 严格 JSON 输出，三层兜底解析
- **错误分诊**：每种失败给一个**能修好的方向**（不是「重试」）

### 语音

- Edge TTS（免密钥、带 7 个英文音色）
- OpenAI 兼容 TTS（`/audio/speech`，6 个音色）
- 音色**按引擎取**（0.0.3 修的，见上）
- 浏览器语音兜底（`speechSynthesis`），语言标签从语言目录取
- 内容寻址：同一句话换音色生成新文件、换回来命中旧文件
- **部分失败不算整体失败**：8 条里挂 2 条 → 拿到「6 条能听、2 条补语音」

### 界面

- 单文件 HTML，零构建、零 CDN、零框架
- **断网可练**（例句和语音都在本机）
- 五通道各自的操作方式和评分
- 打字卡逐词比对（红=漏/错、黄=多打、绿=对）
- hash 路由、键盘操作（空格翻面 / 1-4 评分）

### 工程

- `--check` 自检八项，`--check-deep` 真连一次模型
- `%LOCALAPPDATA%\Etude` 数据目录，与程序目录完全分开
- 备份走 `VACUUM INTO`（不是复制文件）
- 端口占用分类处理（对面是自己 → 复用，不是 → 换端口）
- `/api/health` 自述 pid/版本/数据目录
- 打包 + 归档核对 + 冻结态自检 + 端到端 + 发版脚本

### 测试与守卫

- 113 个用例：逻辑、边界、错误方向、路径穿越、隐私红线
- `check_js.py`：前端调用点 + **事件名大小写**（这条抓过真 bug）
- `ui_smoke.js`：真浏览器点一遍 + 收集控制台错误
- `e2e_check.py`：对打包版打真实 HTTP
- **探针自检**：守卫在给结论之前先验自己

## 四、**没验证**的（这一节最重要）

### 4.1 真人长期使用效果 —— 完全没有验证

代码逻辑是**对着理论写的**（六条主张逐条映射，见 THEORY.md），
但「照着练三个月会怎样」**没有任何数据支持**。

具体说，以下全部是**未经证实的假设**：

- 假设一：8 条例句足以让大脑开始归纳出用法。
  **没有任何证据说明 8 这个数字是对的**，它只是一个「一次生成不贵、看起来够多」的折中。
- 假设二：五种通道分开练比合成一张卡更有效。
  理论上是这么说的，但这个产品**没有做过对照实验**。
- 假设三：「没想起来 → 10 分钟后再来」比「推到明天」更有效。
  这是我加的（原文没提间隔重复）。10 分钟这个数字是拍的。
- 假设四：每次随机给一种中文说法能阻止「英文↔固定中文」的锁死。
  合理，但没有验过。
- 假设五：模型生成的例句质量够用。
  **这条最可能不成立** —— 弱模型给的句子平淡甚至不地道，
  而程序不做任何质量校验。

**这一节存在的意义**：如果三个月后发现效果不好，应该能从这里看出
「是哪个假设错了」，而不是笼统地觉得「这个方法不行」。

### 4.2 只在 Windows 上跑过

- 打包和端到端**只在这台 Windows 机器上验证过**。
- 没有在干净的 Windows 虚拟机上装过（本机有各种运行时，
  「我这里能跑」的证明力有限）。
- **没有测过：** 中文用户名下的路径、没有写权限的目录、
  杀毒软件拦截、公司代理/防火墙环境、显示器缩放不是 100%。
- `paths.py` 里给非 Windows 留了兜底（`~/.etude`），
  **但那行代码从没被执行过**。

### 4.3 模型兼容性只测了 7 家中的「协议层」

- 7 家预置的 base_url 和默认模型名是**照着各家文档填的**，
  没有逐个真机验证过（手上只有一部分厂商的密钥）。
- 豆包的模型名要填**接入点 ID**（`ep-xxxx`）而不是模型名 ——
  这一点在 README 和 QUICKSTART 里都标注了，
  但它的报错信息会不会清晰地指出这件事，**没验证**。
- 真正跑通的只有：本地假模型（`openai_stub.py`）+ 端到端测试里的假 HTTP 服务。
  **这两条覆盖的是「协议实现对不对」，不覆盖「各家的实际行为」**。

### 4.4 语音只测了「能用」，没测「好听」

- 音色列表是 Edge TTS 官方文档里的名字，没有逐个听过。
- 语速/音量的 `+x%` 格式是 Edge 的约定，OpenAI 兼容端点**是否接受同样的写法
  没有验证** —— 大概率不接受，需要转换（见「已知问题」）。
- 长句子的合成质量、边缘情况（数字、缩写、专有名词怎么念）没测过。

### 4.5 并发只有 3 个线程

`ThreadPoolExecutor(max_workers=3)`。同时生成超过 3 个训练包时，
第 4 个会排队 —— **界面会显示「正在生成」，但实际还没开始**。
没有做过「一次生成 10 个包」的测试。

### 4.6 数据规模没压过

- 最大的测试数据是 3 个包 / 24 条例句 / 120 张卡。
- **没有测过：** 几百个包时列表页会不会卡、
  上万张卡时队列查询会不会慢、音频目录上万个文件时的表现。
- `idx_cards_due ON cards (due_at, introduced)` 是按预期建的，
  但没有在真实数据量上验证过执行计划。

## 五、已知问题

| 问题 | 影响 | 打算怎么办 |
|---|---|---|
| Edge TTS 依赖在线接口 | 断网时**新生成的包**没有语音（已生成的包不受影响） | 无解，Edge 本来就是这个性质。已经在文档里说清了 |
| **语速/音量设置在大模型 TTS 下不生效** | `_synthesize_openai()` 的 payload 里只有 `model` / `input` / `voice` / `response_format`，**没有 `speed`**。也就是说选了 OpenAI 兼容 TTS 之后，设置里的语速调节是静默失效的 —— 不报错，只是没作用 | 0.1.x 把它映射成 OpenAI 的 `speed`（0.25~4.0 的浮点数，不是 `+10%` 字符串） |
| 大模型 TTS 的音频缓存会被语速设置分叉 | `cache_name()` 把 `rate` 算进哈希，但上一条说明 OpenAI 路径根本不用 `rate`。于是**只改语速就会重新合成一份内容完全相同的文件**，白占磁盘 | 同上的修复顺带解决：OpenAI 路径把它转换后参与哈希 |
| 豆包模型名要填接入点 ID | 填错会得到 404 | 已在文档里标注；考虑在「测试连接」里专门识别这种错（0.1.x） |
| **训练包详情的地址栏仍是 `#lessons`** | 进详情的 hash 和列表页一样，于是**刷新会回到列表**、浏览器后退也跳过详情。详情页有「返回列表」按钮，所以功能没坏，但地址栏和内容对不上 | 0.1.x 改成 `#lessons/<id>` 路由 |
| **场景配图的检索质量取决于开放图库** | 生僻场景可能搜不到合适的图。搜不到时**留空，不会塞一张不相干的图** | 这是刻意的取舍：塞错图比没图更糟（会把学习者的场景理解带偏）。可以在设置里改用文生图 |
| 严格 JSON 输出对弱模型不友好 | 弱模型会给出格式错的回复，或偷懒给逐字翻译的「场景」 | 三层解析兜底 + 错误提示说清方向。**换模型比改代码有效** |
| 一次生成多个包时会排队 | 第 4 个及以后显示「正在生成」但还没开始 | 界面显示「排队中」（现在也是「正在生成」，措辞可以更准） |
| 生成中途关掉程序 | 那个包会停在 `generating` | 下次启动 `recover_stale()` 会标成 `failed`，可以点重生成 |
| 界面文案只有中文 | 英文用户用不了 | 0.0.3 明确面向中文用户 |
| **「并行配图」的败者线程不会被取消** | 两条路里慢的那条会一直跑到出结果或超时。它不再占着界面，但确实占着一个线程和一次网络请求 | 无解 —— Python 停不掉正在跑的线程。`shutdown(wait=False)` 已经是能做到的全部，代码里也**没有假装**它能被取消 |
| **撤销依赖评分时存的快照** | 0.0.2 及以前留下的复习记录**没有** `prev_state`，对它们撤销会被**拒绝**（不是清零）。写得清清楚楚，但用户会看到一次「撤不了」 | 刻意的：没有快照时清零等于凭空毁掉复习进度。这类记录会随着继续练习自然被新记录覆盖 |
| **暂停的卡需要手动恢复** | 暂停的卡不进队列、也不计入「今天到期」。**没有任何提示告诉你有多少张卡正停着** —— 简易档下完全看不见 | 进阶档在侧边栏显示「已暂停」的数量。可以把「有暂停卡时在训练页提一句」也做上（0.1.x） |
| 手动改 SRS 是「无护栏」的 | 进阶档允许把间隔直接填成 365 天、把卡打回新卡。填错了没有撤销 | 撤销只覆盖「评分」这一种操作，**不覆盖手改**。这是刻意的：手改是明确的意图，不该被当成手滑 |

## 六、边界情况清单

写在这里，是因为「没测」和「测了没问题」是两件事。

| 情况 | 状态 |
|---|---|
| 生成时音频合成部分失败 | ✅ 测了。降级为记录，其余可用，界面出「补语音」 |
| 模型返回带围栏的 JSON（` ```json ... ``` `） | ✅ 测了。`extract_json()` 第二层剥围栏 |

| 端口被旧进程占用 | ✅ 测了。分类处理 |
| 数据库开着 WAL 时备份 | ✅ 测了。走 `VACUUM INTO` |
| 上次崩在 `generating` | ✅ 测了。`recover_stale()` 标 `failed` |
| 重复的例句 | ✅ 测了。`normalize()` 主动丢弃 |
| 空例句 / 空场景 | ✅ 测了。丢弃，不写库 |
| 中文说法少于 3 种 | ✅ 测了。回退到 `scene_zh` |
| 评分值非法（比如 99） | ✅ 测了。接口拒绝 |
| 撤销一张从没评过的卡 | ✅ 测了。404，不是 500，也不是「假装成功」 |
| 撤销一条没有快照的老记录 | ✅ 测了。**拒绝执行**，并且断言数据一个字节都没动 |

| 打回新卡时旧统计没清 | ✅ 测了。断言间隔/次数/遗忘次数/上次评分全归零 |
| 加例句漏铺卡片 | ✅ 测了。断言卡片数正好 +5 |
| 删例句留下孤儿卡 | ✅ 测了。断言那个例句的卡一张不剩 |
| 两条配图路一条超时一条很快 | ✅ 测了。断言**不等慢的那条**（用耗时上界卡住） |
| 两条配图路同时开跑 | ✅ 测了。用 `threading.Barrier(2)` —— 串行的话会卡到超时而失败 |
| 两条配图路都失败 | ✅ 测了。断言错误里**两边各自的原因都在** |

| 磁盘满了 | ❌ **没测** |

但「用不同数据目录/端口起两个」会各写各的 |
| 系统时间被改（往前调） | ❌ **没测**。间隔重复会表现异常 |
| 生成 1000 条例句 | ❌ **没测**。提示词会很长，模型可能截断 |
| **并行配图在真实网络延迟下的表现** | ❌ **没测**。单元测试用的是可控的假桩（能精确控制谁先到），
但「Openverse 真实限流时的延迟分布」只在手动试用里见过 |
| **两条配图路的败者线程泄漏** | ❌ **没测**。理论上每次 `both` 会留下一个跑到自然结束的线程，
没有测过连续几百次之后线程数会不会堆积 |

## 七、如果要给一个「能不能用」的结论

**能用**，前提是你接受这三条：

1. **只在这台 Windows 上验证过**，别人的机器上可能碰到没测过的情况；
2. **例句质量取决于你配的模型** —— 程序不做质量校验，
   弱模型会让整套方法退化成中译英；
3. **效果没有验证过** —— 它没有让任何人变成更流利的英语使用者（据我所知）。

它值得一试的地方在于：上面那些「没验证的假设」如果有一条错了，
你会在两三周内感觉到（比如「例句都差不多，练了几次就不想练了」，
那就是假设一错了），而不是三个月后才发现。
