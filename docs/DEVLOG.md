> **怎么做**、**踩到什么**（只记真的花过时间的）、**怎么验证的**。
>
> 踩坑那部分是这份日志唯一有长期价值的部分：源码读一遍就知道的东西不用记，

## 第 0 轮 · 读材料，定产品形态

**起点**：一张需求单 ——「做一个学习自然语言的工具，接入大模型，做成 exe 发到 GitHub，
版号 0.0.1，先做英语」。

**读了三份 docx + 一份讲稿 + 两篇知乎**，记下六条主张（后来成了 THEORY.md 的骨架）。

**这一轮真正的产出是一个决定**：GitHub 上做「AI 生成语言卡片」的项目已经很多
（mnemorai / han-flash / anki_ai / anki-cards-ai-generator …），
绝大多数是**单词 → 卡片**的造卡器。

要做出区别，只有一条路：**不做造卡器，做训练循环**。
所以产品形态定成「给一个词 → 8 条例句 × 5 种练法 → 自带间隔重复」。

**名字**：Etude（/eɪˈtjuːd/），音乐里的「练习曲」——专为练技巧而写，
不讲故事、不为演出，纯粹为了让手指形成本能。

**四个要用户拍板的问题，得到的答复**：

| 问题 | 答复 | 落成什么 |
|---|---|---|
| 复习方式 | 「先不用管 anki，那是以后要做的」 | 做**内置**训练器，不做 `.apkg` 导出 |
| 大模型接入 | 「两者结合」 | 7 家预置厂商 + 自定义 base_url |
| 语音合成 | 「两者都支持」 | Edge TTS（免费）+ OpenAI 兼容 TTS |
| 项目名 | 「你自己给我取一个」 | Etude |

## 第 1 轮 · 骨架：paths / config / db / srs

**起点**：空目录。

**怎么做**：先定**最容易返工**的四层 —— 这三个都是「等打包了才发现要改、
就得动整条链路」的东西。

- `paths.py`：全项目唯一判断「在不在 exe 里」的地方。三条规则 ——
  可写的进用户目录、只读的进包内资源、**判断只在这一处做**。
- `config.py`：配置存 `%LOCALAPPDATA%\Etude\config.json`，**在仓库外**。
  这不是洁癖，是从根上杜绝「把 API Key 提交上去」这种事故。
- `db.py`：四张表。定主键 `(例句, 通道)`。
- `srs.py`：纯函数，不碰数据库、不碰时间。

**踩到的**：

1. **端口**。上一个项目用的是 8787，那台机器上到现在还留着一堆旧进程，
   手工 `curl` 会打到旧进程上、看到错的版本和错的数据目录。
   这个项目换成 `8977`。**换个不重复的端口比学会「先查再打」便宜。**
2. **BLAS 线程限流必须放在 `app/__init__.py` 最上面**，
   在任何子模块 import 之前。放到 `db.py` 里就晚了 ——
   numpy 一旦被 import 过，这些环境变量就不再生效。
   这个项目理论上用不到 numpy，但 venv 里装着（上个项目的遗留），
   所以入口处先设好 `OPENBLAS_NUM_THREADS=1` 之类，防的是「某次不小心
   import 进来，起 32 个线程抢一个 CPU」。

**怎么验证的**：`test_core.py`。其中一条值得单说 ——
`test_frozen_check_happens_in_exactly_one_place` **全仓搜索 `sys.frozen`**，
断言只有 `paths.py` 里出现。这条测试保护的是「规则一多就会漏」的风险。

## 第 2 轮 · 提示词与两个 provider

**起点**：能存数据了，但没内容。

**怎么做**：

- `prompts.py` 的 `SYSTEM` 里把「**场景是情境，不是翻译**」写成加粗级的强调。
  这是整个项目最容易做错的一处 —— 场景写成逐字翻译，口语卡就退化成中译英，
  整个方法废掉。
- `llm.py`：8 家预置 + OpenAI 兼容协议统一接入。重点是 `explain_error()`。
- `tts.py`：双引擎，内容寻址文件名。

**踩到的**：

3. **`extract_json()` 面对「解说词里有花括号」会放弃**。
   原实现是「找第一个 `{`，配平扫描，失败就返回 None」。
   模型很常见的输出是「好的，这是你要的 JSON： {…} 希望能帮到你 }」——
   直接栽。改成**遍历每一个 `{`** 逐个尝试。

4. **假装 json_mode 一定成功**。有的服务不认 `response_format`，
   回 400。原来的处理是「去掉 `response_format` 重试一次」——
   但这会被算进重试次数，于是「格式不兼容」和「服务不稳定」共用一个预算。
   改成：400 + json_mode 的这次重试**不计入重试次数**。

5. **`explain_error()` 的顺序**。这条来自上一个项目最贵的一类 bug：
   如果「缺组件」判断排在网络关键词之后，用户会收到
   「**重试 / 换个网络 / 换个镜像**」—— 这条建议永远修不好问题，
   因为真正的原因是 `ModuleNotFoundError`。
   现在的顺序是：① `ImportError`/`ModuleNotFoundError` → ② 本机地址连不上
   → ③ HTTP 状态码分类 → ④ 超时/网络 → ⑤ 未知。
   有测试盯着这条，而且断言里写清了「为什么」：
   `assert "重试也不会好" in hint`，因为它确实说了正确的话。

6. **`_synthesize_*` 成功返回但不写字节**。有的音频库会「成功返回」一个
   它其实没写成功的文件。现在合成完**检查文件真的存在且非空**，
   不然会在几十分钟后表现为「有例句但没声音」，而那时已经很难定位了。

7. **音频路径存相对路径**。绝对路径换个数据目录就是死链，
   备份还原到另一台机器全废。

**怎么验证的**：`test_e2e_stub.py` 起真 HTTP 假模型，逐个 fault 断言
「每种故障给出的提示**互不相同**」（只断言「有提示」是不够的，
三种故障给同一句话等于没提示）。另有一条专门断言「三种故障说的话不一样」。

## 第 3 轮 · 流水线、接口、自检、窗口

**起点**：零件齐了，没有装配线。

**怎么做**：

- `pipeline.py`：作业表在内存，`_JOBS`；`recover_stale()` 把上次崩在
  `generating` 的行标成 `failed`。
- `api.py`：`/api/lessons` 立刻返回，生成走后台线程池。
- `server.py`：端口占用的分类处理。
- `selfcheck.py`：八项。
- `desktop.py`：开不了窗口就返回 `False`。

**踩到的**：

8. **`ready` 和 `complete` 合成一个布尔值**。
   第一版 `readiness()` 返回单个布尔值，算的是「例句齐、音频也齐」。
   后果：Edge TTS 抽风 → 整个包判定不可练 → 读写造句四个通道明明好的，
   跟着一起被封掉。
   拆成两个字段，各自对应一种界面行为。

9. **`server.join()` 从窗口关闭回调里调会死锁**。
   表现是「关了窗口，进程还在任务管理器里」。
   改成 `ask_stop()` 只置标志，join 留给主线程（带 5 秒超时）。

10. **无脑换端口会造出两个实例**。
    用户双击两次 exe 是最常见的情况。无脑换端口 → 第二个实例悄悄起在
    随机端口上、开新窗口、两个窗口互相盖同一个 sqlite，
    表现是「数据丢了」。
    改成先 `probe_etude()`：对面应答且是自己 → **复用**。

11. **`/api/health` 要自述**。返回 pid、版本、运行形态、数据目录。
    这条接口的全部意义就是「让旧进程一眼可辨」。

12. **界面 HTML 必须 `no-store`**。
    打包后界面从 `_internal/` 读，浏览器拿旧 HTML 会表现成
    「代码改了但没生效」。宁可每次重读磁盘。

13. **`sys.modules.setdefault("app.desktop", ...)`**。
    PyInstaller 下 `run_etude.py` 里 `import app.desktop` 和
    `app/desktop.py` 内部 `from app import desktop` 有可能变成**两个模块对象**，
    于是「关闭标志」一个模块设了、另一个模块读不到。
    这行 setdefault 防的就是模块分裂。

**怎么验证的**：`test_api.py`。值得单说的两条 ——
「自检在缺窗口时**不能报 fail**」（报 fail 会把一个「能用但没那么好看」
的状态说成「不能用」，那是误导），
以及「音频路径穿越」（`..%2F..%2Fconfig.json` 要在进文件系统前被挡掉）。

## 第 4 轮 · 前端

**起点**：接口齐了，没界面。

**怎么做**：一个 HTML 文件，约 1480 行，零构建、零 CDN、不用框架。

- 不用 CDN：**断网也要能练**。例句和语音都在本机，
  没道理打开界面还要等一个 jsdelivr 请求。
- 不用框架：没有编译步骤 = 双击就能调界面。代价是失去编译期检查 ——
  用 `check_js.py` 补。
- 不用 `innerHTML` 拼字符串：例句里有用户输入的目标词，拼字符串就是 XSS 入口。
  全部走 `el(tag, attrs, children)` 建 DOM。

**踩到的**：

14. **最严重的一个 bug：所有按钮点击都是死的。**
    `el()` 里写的是 `key.slice(2)`，于是 `onClick` →
    `addEventListener("Click", ...)`。
    **事件类型串是大小写敏感的**，一个都不会触发。

    这个 bug 的可怕之处在于它**完全隐身**：
    界面照常画出来；截图看不出来（元素都在）；Python 测试测不到
    （它不跑 JS）；控制台**没有报错**（`addEventListener` 接受任意字符串）。
    只有真在浏览器里点一下才会发现。

    旁证很有意思：这个 bug 存在期间，`screenshots.js` 只能生成 **8 张**
    截图（`04-listen-front.png` 一直缺失 —— 那一步要先点一个按钮才能到）。
    修好之后 9 张齐全。

    修法是 `.toLowerCase()`，然后补了两条守卫：
    `check_js.py` 里的 `bad_event_type_literals()`（查字面量），
    以及 `test_guards.py` 里的反证用例（故意喂一个 `onClick` 进去，
    断言守卫会报）。

15. **`pollLesson` 用单个共享定时器**。同时生成多个包时，
    只有最后一个被轮询，前面那些永远停在「正在生成」。
    改成 `pollTimers = new Map()`，键是 lesson_id。

16. **`retryLesson` 会创建一个名叫 `__retry__` 的训练包**（写的时候
    图省事，让重生成走同一条建包路径）。删掉，改成
    `POST /api/lessons/{id}/regenerate`。

17. **`practiceOne` 靠推算卡片 id**。`card_id = 例句序号 * 5 + 通道序号`
    ——依赖「卡片 id 连续」这个前提，重生成一次就没了。
    改成 `lesson_detail()` 返回 `cards` 清单，前端**查表**。

18. **同一张卡内部中文说法要稳定**。第一版是每次翻面都重新随机取一种，
    读起来像界面在抖。改成 `state.variantIndex` 在 `fetchCard()` 时定下来。

19. **`loadStats` 未定义**（守卫抓到的）。删掉那两处调用。

**怎么验证的**：`check_js.py`（73 处调用全部有定义 + 事件名大小写）、
`ui_smoke.js`（真浏览器点一遍，21/21 通过，同时收集控制台错误）。

## 第 5 轮 · 守卫被自己骗了（这一轮最值钱）

**起点**：`check_js.py` 第一次跑，报了 **8 个「函数未定义」**。

**看起来**：8 个我明明写了的函数被报未定义。

**真相**：探针坏了，伪装成被测对象坏了。

`diffWords` 里有个正则字面量 `/[^a-z0-9' ]/g`，里面那个单引号被朴素的
清洗器当成字符串开头，于是它从那里开始吃，一直吃到下一个单引号 ——
**中间一大段代码整个被当成字符串吃掉了**，里面定义的函数自然「不存在」。

**修法**：

1. 加 `_regex_allowed_before(text, index)`，判断一个 `/` 到底是正则开头
   还是除法运算符（看前一个非空白字符：是标识符/数字/`)`/`]` 就是除法，
   否则是正则）。顺便处理了正则自己的字符类 `[...]` 里的 `/`。
2. 加 `_SELF_TEST_SAMPLES`（5 个样本，覆盖「正则里带引号」「除法」
   「注释」「字符串」「模板串」）+ `self_test()`。
   **每次运行在给结论之前先验探针本身。**

**验证**：把 `function reveal()` 改名成 `revealTheCard()`，
守卫报 `index.html:1366 reveal()`、退出码 1。**探针能失败才算探针。**

**这一轮的教训值得单独记**：
> 探针坏了会伪装成被测对象坏了。
> 而它给出的错误方向（「你有 8 个函数没定义」）会让你去改**完全正确**的代码。

## 第 7 轮 · 打包

**起点**：源码态全绿。

**怎么做**：onedir（不是 onefile），`console=True`，显式 `excludes`。

**踩到的**：

27. **onedir vs onefile**。onefile 每次启动解压到临时目录、
    **退出即删** —— 用户会以为数据丢了。
28. **`excludes` 不是可选的**。开发 venv 里装着上个项目的
    faster-whisper / onnxruntime / tokenizers / av / soundcard，
    PyInstaller 会顺着 import 图全拉进来。显式切断后 **49.0 MB / 125 个文件**。
29. **归档核对不能用 `grep` 二进制**。拿 `grep` 去 exe 里找模块名，
    假阳性一堆（字符串池里有大量偶然命中）。
    改用 PyInstaller 自己的归档读取器，查 10 个必需模块。
    少一个就**不产出 dist**。
30. **体积报警只报不失败**。超 260 MB 打印警告。失败会把合理的增长
    （加了功能）也拦下来。
31. **`--check` 必须在控制台跑**。所以 `console=True` 不能关 ——
    它是「双击没反应」的唯一出口。

**怎么验证的**：`build_exe.py` 六步 —— 前置守卫 → 版本一致 → 打包
→ 归档核对 10/10 → 体积 → **冻结态跑 `--check`**。
然后 `e2e_check.py` 对打包版打真实 HTTP：**18/18 通过**。
用临时数据目录（`ETUDE_DATA_DIR` 指到系统临时目录），完全不碰真实数据。

## 第 8 轮 · 截图、文档、以及一个被安全策略挡下来的验证

**起点**：功能齐了，要出文档。

**怎么做**：`screenshots.js` 用自写的 CDP 客户端（`cdp.js`）驱动本机 Chrome，
生成 README 的 9 张截图。

**踩到的**：

32. **截图被系统显示缩放压小**。设了 `SHOT_WIDTH=1400`，
    PNG 实测 1080 宽。Chrome 要加 `--force-device-scale-factor=1`
    —— 不设的话，任何有显示缩放的机器上图都会糊。
33. **截图必须脚本化，不能手截**。理由很直白：
    **旧图比没有图更糟。** 手工截的图在下一版就会开始说谎，
    而脚本化的图跑一次就能跟上。
34. **PowerShell 启动 GUI 程序被安全策略拒绝**。
    我本来想「起一个窗口，确认它开得起来」。
    报错是「Invoking PowerShell from Bash bypasses PowerShell security checks」。

    **没有强行绕过。** 改成把「原生窗口可用性」做成 `selfcheck.py` 里的
    八项之一（`_window_status()`），缺 WebView2 只报 `warn` ——
    因为会退回浏览器、功能一样。**这是更有价值的做法**：
    它变成用户能自己跑、能自己看见的一项检查，
    而不是我在这里替所有机器验证一次。

**怎么验证的**：9 张截图齐全（1400×940，深色主题）、
`ui_smoke.js` 21/21、113 项测试通过。

## 这一版没做的事

留着防止下次有人以为「忘了」：

- **Anki 导出**（`.apkg`）—— 用户明确说「先不用管 anki，那是以后要做的」。
- **发音打分 / 语音识别**—— 需要参考音素序列和打分模型（几百 MB），
  0.0.x 的目标是先把卡片循环跑通。**这是范围决定，不是否定它的价值。**
- **英语以外的语言** —— 用户说「先用英语为开头」。
  架构上只差提示词分支和音色表（见 THEORY.md 第四节）。
- **macOS / Linux 桌面包** —— 只在 Windows 上打包和验证过。
- **真人长期使用效果** —— 代码逻辑对着理论写了，
  但「照着练三个月会怎样」没有任何数据支持，也不应该被声称。

## 第 9 轮 · 发版：两个「第二次才暴露」的坑

**起点**：文档写完，准备发 v0.0.1。

**踩到的**：

35. **第二次打包必定失败，而且报错完全指错方向。**

    PyInstaller 在 COLLECT 阶段会先 `_rmtree` 已存在的输出目录
    （`PyInstaller/building/api.py`，注释写着「will prompt for confirmation
    if --noconfirm is not given」）。

    本机有一层批量删除保护：一次删 >50 个文件需要人工确认。
    脚本里的确认传不进去，于是每次重建都在这里死掉，
    而 `build_exe.py` 报出来的只有一句 **「PyInstaller 失败了」**——
    看这个提示会去查 spec、查依赖、查版本，全都不相关。

    修法是 `scripts/products.py`：**不去删旧目录，换一个空位写新产物**
    （`dist/Etude` → `dist/build2/Etude` → `build3`…）。
    `build_exe` / `make_release` / `e2e_check` 共用它的 `newest_output()`
    去找最近一次的那份 —— 按 `Etude.exe` 的**修改时间**排序，
    不按目录名（`build2` / `build10` 按字符串比会得到错的顺序）。

    附带的好处正好是想要的：上一份产物还在，体积对比和回滚都不用重新打包。

36. **zip 不可复现，「校验和印在说明里」这条检查因此永远过不去。**

    `--check` 算出的哈希是 `f374bcb6…`，印进发行说明，正式发版时却算出
    `26e077fe…`，脚本拦住不让发。看起来像「说明是旧版本留下的」，
    但实际原因是：`zipfile.writestr(name, text)` 建 ZipInfo 时用的是
    **`time.localtime()[:6]`**，也就是打包那一刻。

    于是同一份产物、同一个文件名，两次打包得到两个不同的哈希 ——
    那么「把校验和印在说明里，让用户核对」这件事从根上就是假的。

    修法：所有条目统一写一个固定时间戳（ZIP 的 DOS 时间最小年份是 1980，
    写更早的值会被钳成 1979，反倒让部分解压工具报错）。
    改完连跑两次，哈希一致。

    **这一条值得单独记**：它和第 5 轮那个教训是同一个形状 ——
    一个检查报错时，先确认检查本身是不是错的。
    如果当时直接「按提示把新哈希抄进说明」，就会把一个不可复现的产物发出去。

**怎么验证的**：

- 打包：49.1 MB / 133 个文件，归档核对 **10/10**，冻结态 `--check` 通过
  （唯一一项 `WARN` 是「还没填密钥」，符合预期）
- 端到端（对**打包版**打真实 HTTP）：**18/18**
- zip 连跑两次哈希一致
- 推送到 GitHub 后从 Releases 页实拉一次，大小和哈希都对得上

## 第 10 轮 · 0.0.2：场景图片化、学习计划、数据搬迁

**起点**：用了一天之后提的六条意见。原话里最关键的两条是：

> 「我期望的『场景』是图片或视频，偏图片」
>
> 「我不希望是我刚才说的很朴素的拿个程度等级去设置目标，
> 我希望的是学会一门语言的听说读写认，字面意义上的学一门语言，
> 填六级这样的程度只不过是我需要过了考试。」

第二条直接推翻了「难度下拉框」这个自然的做法 —— 见
[THEORY.md 那一节](THEORY.md#002-补的一块目标--难度标签)。

**做法**：

| 需求 | 落点 |
|---|---|
| 场景给图 | `providers/images.py`：图库检索 / 文生图 / 关闭三选一 |
| 目标导向 | `plans` 表 + `draft_plan()` / `generate_plan()`，先大纲后开工 |
| 交互键进侧边栏 + 收缩 | 前端加 `.side`，状态存 localStorage |
| 评分键按不动 | 查出来是 `disabled` 但保留了手形光标 |
| 数据位置可改 | `storage.py`，只写指针、不删旧数据 |

**踩到的坑（按值钱程度排）**：

1. **「升级就崩」的顺序 bug。** `connect()` 里先建表、再迁移。老库里
   `lessons` 表已有、`plan_id` 没有，`CREATE TABLE IF NOT EXISTS` 是空操作，
   紧跟的建索引直接报 `no such column`。**每个 0.0.1 用户每次启动都崩**，
   而开发机上永远是全新库、永远不出现。
   `test_upgrade.py` 就是为这类「只在升级路径上出现」的问题建的。

2. **端到端检查悄悄变成了「外网可用性检查」。** 场景配图默认来源是图库检索，
   而 `e2e_check.py` 只配了 `llm` 和 `tts`。于是打包版一生成就去联网，
   网慢的时候卡在 `generating` 直到超时，报出来是「训练包生成失败」——
   看着像生成的 bug，方向全错。修法是在检查里显式指定配图来源。

3. **`_sniff` 的兜底把错误页存成了图片。** 原来的实现认不出格式就返回 `.jpg`。
   图床出错时爱返回「200 + 一页 HTML」，于是存出一张**永远加载不出来的假图**，
   而「文件非空」的断言一路放行。现在认不出就返回空串 + 抛错。

4. **`Path("   ").resolve()` 会变成当前工作目录。** 于是「填了一堆空格」
   被当成「搬到当前目录」，而且测试里还断言它该失败 —— 测试反过来抓住了实现。
   修法是**在 `resolve()` 之前**先 `strip()` 判空。

5. **截图脚本卡在一个 hash 导航的坑上（花的时间最多）。**
   现象：脚本跑两步就报「等不到训练包列表」，而手工探针每次都对。
   `openLesson()`（点「打开」进详情）会把 `location.hash` 也设成 `#lessons`，
   于是脚本后面那次「goto 到 `#lessons`」变成了**同 hash 导航** ——
   `hashchange` 不触发，前端里 `if (next !== state.view)` 的比对也不成立，
   页面**留在详情页**，`.lesson` 自然永远是 0。

   定位它靠的是给 `cdp.js` 的 `evaluate` 加了一个 `SHOT_DEBUG` 开关，
   把页面上跑过的每一段脚本打出来 —— 一打就看见那条 `FIRST_LESSON` 的
   `.find(...).click()` 在预期之外出现了。**光看报错是查不出来的**，
   因为报错说的是「列表没出来」而不是「你其实在详情页」。

   顺带确认了一件事：**详情页的状态没进 URL**。这是已知限制（刷新回列表），
   记进了 STATUS，0.1.x 再改成 `#lessons/<id>`。

6. **假模型返回 1×1 像素的图。** 截图里场景图的位置看上去永远像「图没加载出来」，
   会让人去修一个根本不存在的 bug。改成 320×200 的真彩色渐变 PNG，
   并把理由写进 docstring。

**怎么验证的**：

- 测试 **187 个用例**（0.0.1 是 113），其中 70 个是这一轮新增的
- `check_js.py`：**121 处调用点**全部有定义
- `ui_smoke.js`：**54/54**，四个评分档改成真实鼠标事件逐个点
  （0.0.1 漏掉那个 bug 就是因为当时用 `evaluate("grade(2)")` 绕过了 DOM 事件层）
- `e2e_check.py`：**20/20**，含「配图取回来真的是图片」这一项
- 打包 **49.2 MB / 133 个文件**（+0.1 MB），冻结态自检通过，
  自检里多了「场景配图」一项
- 界面截图重出 14 张，全部走真实点击

## 第 11 轮 · 0.0.3：修静默静音、配图并行、Anki 式调控

**起点**：用过 0.0.2 之后提的七条。其中第 3 条「语言读不出来，检查一下问题」
是唯一一条**报故障**的，其余都是改进意见。事后看，那条故障是这一版最值钱的收获。

原文：

> 1.「没想起来、吃力、正常、秒答」这些东西不放到侧边栏，就放到「训练」里。
> 2.界面颜色还是不够护眼美观，再优化。
> 3.语言读不出来，检查一下问题。
> 4.图片生成质量不行，要生成图片和检索图片或其他办法并行。
> 5.要有回到上一步和直接下一步的功能。
> 6.「没想起来、吃力、正常、秒答」都可以点，但是显示有点问题，解决一下。
> 7.要学习anki编辑灵活度高，既要保证新手友好，又要注重老手调控。

**做法**：

| 需求 | 落点 |
|---|---|
| 1 评分键回训练页 | 侧边栏竖排 → 卡片正下方横排四列 |
| 2 护眼配色 | 三套（暖白默认 / 冷白 / 深色）+ 跟随系统，字号三档同时给 |
| 3 读不出来 | `tts.resolve_voice()` + `tts.synthesize_cfg()` + 自检真的出声 |
| 4 配图并行 | 新来源 `both`（成为默认），先到先得 |
| 5 上一步 / 下一步 | `prevCard()` / `nextCard()` / `undoLastGrade()` |
| 6 评分键显示 | 待用状态改用「先看答案」小标签，间隔照常显示 |
| 7 Anki 式灵活度 | 界面密度两档 + 卡片编辑器 + 卡片浏览器 + 暂停 / 批量 / 手改 SRS |

**踩到的坑（按值钱程度排）**：

1. **第 3 条那个故障的根因是「音色取错了引擎的那一套」。**
   配置里有两个互不通用的音色字段：`tts.voice`（Edge 的
   `en-US-AriaNeural`）和 `tts.openai.voice`（`alloy`）。
   但合成、补语音、试听三条路径**一律只读 `tts.voice`**。
   于是用户一切到「大模型语音」，程序就把 Edge 的音色名发给 `/audio/speech`
   → 400 `Invalid voice` → **每一条语音都失败，整包静音**，
   而失败只写进日志。界面上是一次静悄悄的全包没声音，
   设置页看着一切正常 —— 因为自检当时只 `import edge_tts` 就算过了。

   定位方式值得记下来：**先证明通道本身是好的**。直接跑一次 `edge_tts`
   拿到 20016 字节、文件头 `\xff\xf3`，由此排除「网络不通」，
   把范围锁到「参数不对」。剩下的事就是去找参数是从哪来的 ——
   一路读下来只有两个音色字段，而代码里只读了一个。

   修法不只是改那一行：音色的取法**收敛到唯一一处**
   （散在三处的话，下次加第三个引擎还会漏）。
   自检也从「import 一下就过」改成「真的合成一句」——
   **一个检查如果不会失败，它就不是检查**。

2. **冒烟脚本自己选错了卡片，于是这条用例常年红着，而毛病在用例身上。**
   想选「深色」主题，写的是「找文字里含『深色』的卡片」。
   但「跟随系统」那张卡的说明是「白天暖白，系统切到深色时跟着变」——
   里面有「深色」，而且在 DOM 里排第一。于是每次都选中它，
   点下去等于把主题设回 `auto`，底色当然不变。
   更糟的是紧邻的那句断言写的是「找到并点了吗」，
   所以它一直**报 OK**，只有下一句「底色变了吗」在红。

   教训有两条：**别用文案当选择器**（给每个选项加了 `data-opt`），
   以及**断言要断在结果上，不要断在「我找到按钮了」上**。

3. **两处界面 bug 是这次的改动自己暴露出来的**（都不是新写的代码，
   是「改密度」和「关抽屉」这两条新路径把旧问题照出来了）：
   - **抽屉不跟着重画。** 抽屉挂在 `<body>` 上、不在 `#app` 里，
     而 `render()` 只重画 `#app`。后果不只是「慢一拍」——
     **改界面密度的开关恰好就在抽屉里**，用户在抽屉里点「进阶」，
     画面纹丝不动，正是这一版反复在修的那种「点了没反应」。
   - **关掉抽屉会掉回训练包列表。** `renderLessons()` 永远画列表，
     不认「我现在停在哪个包」。于是用户改完一条例句一关抽屉，
     眼前从「这个包的 8 条例句」变成「新建训练包」的表单，
     会以为刚才那个包被自己弄丢了。

4. **发版脚本差点发出去一个「标签写 0.0.3、内容是 0.0.2」的包。**
   `dist/` 下留着上次构建的目录，`newest_output()` 老老实实挑它
   （它确实是最新的），打包、算 SHA256、上传**全部成功**，
   只有内容是错的。我是顺手 grep 了一下产物里的前端版本常量才发现
   `APP_VERSION = "0.0.2"`。

   这类「标签对、内容错」比打包失败糟得多 —— 没人会去怀疑它。
   修法是在打包前**核对产物里的版本常量**，不一致就拒绝，
   并说清「dist 下每个目录都是某一次构建的快照，最新的那个不一定是你要发的那个」。
   顺便也验证了这道闸真的会拦（故意指到旧目录，被拒）。

5. **并行配图里，「先到先得」和「都等再择优」是两个完全不同的东西。**
   一开始很自然会想「两个都拿到再挑更好的」，但检索 1–3 秒、
   画图 8–25 秒，差一个数量级 —— 等两个都到，等于把画图的慢
   **加**在检索身上，那就不是并行了。而「择优」需要一把能比较
   「真照片」和「画出来的图」的尺子，这件事没有客观答案，
   硬编一个权重只会让结果变得不可解释。

   先到先得反而有个**可解释的必然结果**：绝大多数时候检索赢
   （用户拿到真照片），只有检索限流 / 搜不到 / 超时时画图才接上场。
   这恰好就是想要的优先级，而且是「顺带实现的」。

   还有一个刻意的「不做」：退出时 `shutdown(wait=False)`，
   **不假装能取消**正在跑的线程。Python 停不掉它，
   写个 `cancel()` 只会让读代码的人以为它真的被停了。

6. **撤销的语义要写清楚，否则用例会在实现完全正确的时候红掉。**
   第一条撤销用例的期望值是「等于评分之前」，但评了两次只撤一次 ——
   正确结果是「等于第一次评分之后」。**是测试写错了，不是代码错了。**
   把「撤一步 = 退一步，不是回最初」写成两段（撤一次回第一步、
   撤两次回最初）之后，才真的验到了快照有没有被原样写回。

   同一功能里另外两个决定也值得记：
   - 撤销**要连 `reviews` 那一行一起删**。那张表是「今天已经练了多少」
     的依据（`due_cards()` 数它来决定放多少新卡），撤了评分却留着记录，
     用户会莫名其妙地发现新卡配额被吃掉了。
   - 老记录（0.0.2 之前）没有 `prev_state` 快照时**拒绝执行**。
     退化成「清零」会凭空毁掉用户的复习进度，而且不报任何错。

7. **几个「我的测试自己写错了」的地方，列出来因为它们都是同类陷阱**：
   - `force=True` 会绕过缓存，所以「验证缓存被复用」的用例必须用
     `force=False` —— 不然它在测的是「有没有重新下载」。
   - `_lesson(2)` 造的是 10 张卡（2 条例句 × 5 通道），
     不是 2 张。写死数字的断言会在**通道数一变**时以「像逻辑坏了」的样子红掉。
   - 「没想起来」会把 `interval` 设成 0（重来间隔是**分钟**级的，
     由 `delay_minutes` 承载），所以不能拿 `interval > 0` 当「学过了」的证据。
   - 前端读的是 `r.changed`，我一开始写成了 `r.pushed`。
     **这恰好就是我在同一条用例里想守的那类 bug**（接口 200、数据也改了，
     但横幅上写「把 undefined 张卡往后推了 7 天」）——
     所以那条用例现在专门断言字段名。

8. **截图编号的算术 bug。** 主题截图用 `"1" + (8 + i)` 生成编号，
   `i=2` 时得到 `110`，文件名成了 `110-theme-dark.png`，
   排在 `11-` 后面 —— 肉眼几乎看不出错，而 README 里引的又是另一个名字。
   改成写死一张名字表。

   顺带把三张配色图的中文说法固定成同一句：中文场景是**随机挑一条**的，
   不固定的话三张并排的图会显示三段不同的中文，读起来像三张不同的卡，
   而这几张图要说明的恰恰是「同一屏，三种皮肤」。

9. **pydantic 的字段名撞上了 `BaseModel` 的方法。** 例句的「语域」字段
   想叫 `register`，而 `BaseModel` 上已经有 `register`，会把它盖掉
   （pydantic 会警告）。改成字段名 `register_text` + `alias="register"`
   + `populate_by_name=True`，存的时候 `model_dump(by_alias=True)`。
   和 0.0.2 踩的 `DataLocationIn.copy` 是同一类问题。

**怎么验证的**：

- 测试 **273 个用例**（0.0.2 是 187），新增 4 个文件：
  `test_anki_controls.py` / `test_edit_api.py` / `test_image_parallel.py` /
  `test_tts_voice.py`
- `check_js.py`：**169 处调用点**全部有定义
- `ui_smoke.js`：**95/95**。新增的断言里有几条是**反过来验**的：
  评分键必须在训练页**且**侧边栏一个都没有；待用的档位**照样**要显示间隔；
  暂停之后去接口查队列**确认那张卡真的不在**（只数界面上几行变灰证明不了后端生效）；
  三套配色的底色两两不同，且深色浅字、浅色深字（只查一边，
  「所有主题都用浅字」这种错误照样能过）
- `e2e_check.py`：**20/20**，对打包版打真实 HTTP，配图来源显式设成
  「只用文生图」（不指定就会变成「外网可用性检查」）
- 打包 **51.5 MB / 144 个文件**（zip 25.6 MB，两次打包 SHA256 一致），
  冻结态自检通过，自检里能读出新的措辞
  （「检索 + 画图 并行」「没实测（加 --deep 会真的合成一句）」）
- 界面截图重出 **20 张**，新增卡片浏览页、编辑器两档、三套配色对照

**这一轮最想记住的一条**：用户报的是「读不出来」，
真因是「程序把一个引擎的音色名发给了另一个引擎」。
两个音色字段并存本身没错，错的是**取音色的地方有三处**。
把「唯一的取法」和「会真的失败的检查」这两件事做上之后，
这类 bug 才不可能再悄悄回来。
