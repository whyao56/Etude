# 理论 → 产品：Etude 为什么长成这样

> 这份文档回答一个问题：**《学习观 07》讲的道理，在这份代码里具体变成了哪一行？**
>
> 每一个功能都对应原文的一句主张。凡是原文没有要求的，「不做」也写在这里 ——
> 知道为什么不做，和知道为什么做一样重要。

---

## 一、原文的六条主张

来源：《学习观 07 · 我们十几年的外语教学的方法几乎全错了》（B 站 BV1TU4y197jU，
讲稿整理见 `C:\Users\HP\Desktop\学习观07.txt`），以及两篇配套的知乎文章
（[p/51717106](https://zhuanlan.zhihu.com/p/51717106)、
[p/52208883](https://zhuanlan.zhihu.com/p/52208883)）。

| # | 原文主张 | 原文里的说法 |
|---|---|---|
| 1 | 语言是**运动类知识**，不是思考类知识 | 「靠意识思考学不会，得靠例子反复训练大脑自动找规律」 |
| 2 | 以**句子**为单位，不是单词 | 「语言的输入是句子，不是单词」 |
| 3 | 同一句话要**用大量不同例子重复** | 「关键不是重复同一个句子，而是不同例子的重复」 |
| 4 | 输入输出要**直接关联**，中间不能夹东西 | 「图片、文字、声音、欲望、意思都是不一样的东西」 |
| 5 | 中文解释**每次都要不同** | 「每次中文解释都不同。就是「输出始终一致」的逆向应用」 |
| 6 | 听说读写是**四种能力，要分别练** | 「第三步是学习阅读，第四步是学习打字，第五步是学习听力，第六步是学习口语」 |

## 二、逐条落到产品上

### 主张 1 → 五种通道各建一张卡，而不是「一张卡多用途」

**原文**：「语言是一种运动类知识，靠意识思考学不会。」

**产品**：数据库里，一张卡的主键是 `(例句, 通道)`，不是 `(单词)`。

```
backend/app/db.py
CHANNELS = ("read", "listen", "speak", "type", "build")
...
for example_id in example_ids:
    for channel in CHANNELS:
        conn.execute("INSERT INTO cards (lesson_id, example_id, channel, ...)")
```

**为什么**：运动类知识的能力是**分化**的 —— 看得懂不等于听得出，听得出不等于说得出。
把它们合成一张「认识这个词」的卡，等于默认它们可以互相迁移，而原文明确说不行。
所以 8 条例句会产生 40 张卡，每张独立调度。

---

### 主张 2 + 3 → 卡片按例句铺，且明确拒绝重复例句

**原文**：「语言的输入是句子，不是单词」「关键不是重复同一个句子，而是不同例子的重复」。

**产品**：规范化那一层**主动丢弃重复的例句**。

```
backend/app/pipeline.py   normalize()
for item in raw_examples:
    if not sentence or sentence.lower() in seen:
        # 重复的例句几乎没用 —— 理论要的是「不同例子的重复」。
        continue
```

提示词里也把这条写成硬约束：

```
backend/app/prompts.py   SYSTEM
7. Do not repeat the same sentence pattern with only the noun swapped; \
   vary the situation, the register, and the sentence structure.
```

**为什么**：如果一个包里有 8 张卡但只有 3 个不同的句子，那 5 张重复的卡
只是在练「记住这一句」，而不是「让大脑自己找规律」。丢掉它们比留着更划算。

---

### 主张 4 → 「场景」的定义是整个项目的关键设计

**原文**：「在学习听力的时候千万不要把声音关联到图片后再关联到意思。」

**产品**：口语卡和打字卡的正面显示的是**场景**，而场景的定义被写死在提示词里：

```
backend/app/prompts.py   SYSTEM
- "Scene" means THE SITUATION IN WHICH SOMEONE WOULD SAY THIS SENTENCE —
  not a translation of the sentence. This is critical: the app shows the
  scene as a prompt and asks the learner to produce the English. If your
  scene is just a literal translation, the exercise degrades into
  translation practice and the whole method fails.
```

**为什么这是最容易做错的一处**：如果把场景写成「任何人都能欣赏我们的音乐」，
那么口语卡就变成了中译英练习 —— 学习者在做**翻译**（意识参与、慢、可思考），
而不是在从场景**直接到表达**（自动、快、不思考）。整个方法就废在这里。
所以提示词里用了加粗级别的强调，并且在 `tests/test_storage_pipeline.py`
里有一条测试盯着这句话还在不在：

```python
def test_prompts_forbid_translation_shaped_scenes():
    assert "SITUATION" in SYSTEM
    assert "not a translation" in SYSTEM or "NOT a translation" in SYSTEM
```

**听力卡刻意不经过图片**：`listen` 通道的正面只有声音，没有图。
加图会引入「声音→图片→意思」这条转接，正是原文点名的错误。

**0.0.2 加了场景配图，这条边界因此更需要说清。**

现在「场景」这一侧（口语卡正面、打字卡正面、以及翻面后的场景区）
可以是一张图 + 一句中文。这和上面禁止的那条路**不冲突**，区别在于**图放在哪一段**：

| | 路径 | 判定 |
|---|---|---|
| 允许 | 场景（图 + 中文）→ 英语表达 | ✅ 图属于**场景**，学习者看到的是「什么情况下说这句话」 |
| 禁止 | 声音 → 图 → 意思（听力卡） | ❌ 图插在**声音和意思之间**，把一条直接通路断成两截 |
| 禁止 | 英语句子 → 中文翻译 | ❌ 那是翻译训练，不是建立表达 |

所以配图是**只加在场景侧**的：听力卡正面永远没有图，阅读卡正面（英文句子）
也没有图。有了这条约束，「加图」是增强场景，而不是在语言输入和意思之间
多插一道转接。

**另一个仍然成立的理由**：光有一行中文描述的场景，太容易退化成中译英 ——
「有人担心台下听不懂，你说谁都能听得进去」和「任何人都能欣赏我们的音乐」
在形式上离得太近了。一张图能把场景**锚定在画面上**，而不是锚定在一句中文上。

### 主张 5 → 同一句话存多种中文说法，复习时随机取一种

**原文**：「不要查看一一对应的中文意思。每次中文解释都不同。」

原文给的例子很有说服力：`I'm afraid I succumbed to temptation and had a piece
of cheesecake.` 有三种都不一样的说法 ——「没忍住偷吃了」/「看着眼前的芝士蛋糕，
我最终还是没能控制住我自己，第二天胖了2斤」。

**产品**：数据库里每条例句存一个 `zh_variants` 数组：

```
backend/app/db.py
    zh_variants TEXT NOT NULL DEFAULT '[]',   -- JSON 数组
```

界面在**每次打开一张卡**时随机挑一种，并且同一张卡内部保持不变：

```javascript
// backend/frontend/index.html
state.variantIndex = variants.length > 1
  ? Math.floor(Math.random() * variants.length) : 0;
```

**为什么随机而不是全显示**：全显示的话，学习者会拿三种说法去**推导**英文该怎么写，
又回到思考类知识的路子上。随机给一种，他就只能从场景本身出发。

**为什么同一张卡内保持不变**：让中文每次翻面都变，读起来像界面在抖，
用户会以为是 bug。（这一条是实机看过才发现的。）

### 主张 6 → 打字卡做逐词比对，而不是「对/错」

**原文**：「第四步：想象要表达这个场景，实际打字发给某人 —— 这是在学习打字。」

**产品**：打字卡提交后做逐词比对，标出**漏了什么、多了什么**：

```javascript
// backend/frontend/index.html
function diffWords(typed, target) { ... }
// 红色波浪线 = 漏掉或打错，黄色 = 多打的，绿色 = 对上的
```

**为什么不做相似度百分比**：学习工具里，「哪几个词对了」比「相似度 73%」有用得多。
百分比不能告诉学习者下一步该干什么。

### 0.0.2 补的一块：目标 ≠ 难度标签

原文的六条主张回答的是「**怎么练**」。0.0.2 补的是另一个问题：
「**练什么、练到什么程度**」。

最初的版本只能一个词一个词地建包。这有个很实际的麻烦：**光是输入内容本身就
占掉大量时间**，而且容易东一个西一个地攒，没有一个整体。

很自然的做法是让用户「选一个难度等级」。**这是一个错误的抽象。**

因为「过六级」和「真的会这门语言」是两件不同的事：

| 用户说的 | 实际意思 | 程序该按什么排 |
|---|---|---|
| 「我要过六级」 | 我需要通过一场考试 | 按考试的范围和形式 |
| 「我要真的学会英语」 | 我要在真实情境里听说读写 | 按「能在什么场合用出来」 |

把它们做成同一个「难度下拉框」，等于假设「等级高 = 会用」。
而考试大纲里大量是**能考但不能用**的东西 —— 这正是原文反复强调的
「思考类知识 ≠ 技能」。

所以程序里是**两条不同的提示词路径**：

- `fluency`：目标是听说读写认五条腿都站起来。大纲要覆盖高频功能词、
  固定说法和句型，而不是一张词表。
- `exam`：**考什么由你给，但内容不按词表排。**
  提示词里写死了一句
  `A list of "important words" is a FAILED syllabus` ——
  因为「重要单词表」恰恰是考试大纲最常见的形态，也正是最不能拿来练技能的形态。
  预设里的 CEFR band **只当范围参考**（别拿 C2 的句子去考四级），不当学习内容。

**还有一个设计上的直接后果**：先生成大纲、让用户勾选，再开工。
不这么做的话，模型会一口气建 20 个包 —— 里面必然有几个是用户早就会的，
时间和钱都白花。**「用户看得见要建什么」比「少一次点击」重要得多。**

### 0.0.3 补的一块：保护间隔重复的**输入**

间隔重复本身是个很朴素的想法：在快要忘的时候再遇到一次，而且每次遇到的是
不同的例子。它的**算法**（这里就是个简化版 SM-2）其实无关紧要 ——
真正决定它有没有用的，是**喂进去的数据**。

但「喂进去的数据」恰好是最容易被弄脏的：用户手滑点错一档、
今天不想看这一批、或者只是想把刚才那张退回去重评一次 ——
这些都会静默地改变一张卡的排期，而排期一乱，后面几周的节奏就全乱了。

所以 0.0.3 加的三样东西，**都不是「顺手做的便利功能」，
而是维持数据可信所必需的**：

| 功能 | 不做的后果（理论上的） |
|---|---|
| **跳过不计入「本次已练」** | 「本次已练」是一个**会被人相信的数字**。逼人为了完成数字而评分，得到的就是假数据 —— 而假数据进了排期，间隔就失去意义了。所以「下一张」是跳过，不是「随便给个评分」。 |
| **撤销要能真的退回去** | 一次手滑评错档，会把这张卡推到完全错误的节奏上；而用户**知道**自己点错了，却改不了 —— 那他接下来会开始不信任自己打的分。信任一旦没了，整套循环就散了。 |
| **暂停（而不是删除）** | 「今天不想看这一批」是真实需求。不提供的话，用户会用「删掉」来替代 —— 而删掉会连进度一起丢。**给一个不丢进度的出口，比劝用户「坚持一下」有效。** |

同一块里还有一条更细的：**撤销必须连那次复习记录一起删掉**，
而且**老记录没有快照时要拒绝执行**。
这两条看着像实现细节，其实都是同一个问题的两面 ——
**「界面显示的进度」和「数据库里的进度」必须始终是同一个东西**。
前者不同步会让用户看到假的进度，后者清零则会让真实的进度凭空消失。

**一个刻意的边界**：撤销只覆盖「评分」，**不覆盖手动改 SRS**。
手动改间隔是一件**明确表达了意图**的操作，不该被当成手滑。
把两者混在一个撤销栈里，最后会变成「我明明改好了，怎么又变回去了」。

## 三、哪些功能是**刻意没做**的

知道没做什么，和知道做了什么一样重要。

| 没做 | 为什么 |
|---|---|
| **不在听力卡上放图片** | 原文明确禁止「声音→图片→意思」这条转接。 |
| **不给语法讲解、不留语法笔记字段** | 原文：「意识能解决单一因素且对速度没要求的知识，声音这种多因素且对速度有要求的知识超出意识能力范围。」讲语法是在喂意识。 |
| **不做「一个词一张卡」的模式** | 原文以句子为单位。单词只在例句里作为「必须出现」的约束存在。 |
| **不给「中译英」练习** | 那是翻译训练，属于思考类知识。场景卡的存在就是为了避开它。 |
| **不做发音评分 / 语音识别打分** | 需要有参考音素序列与打分模型（几百 MB），而 0.0.x 的目标是先把卡片循环跑通。**这是范围决定，不是否定它的价值。** 见路线图。 |
| **不做 Anki 导出（.apkg）** | 用户明确说了「先不用管 anki，那是以后要做的」。注意区分：0.0.3 加的是**Anki 式的调控**（暂停 / 手改间隔 / 批量推后 / 卡片浏览器），不是 Anki 的**数据交换**。前者是「让这个工具自己更好用」，后者是「把数据交给别的工具」。 |
| **不支持英语以外的目标语言** | 用户明确说了「先用英语为开头，以后再增加其他自然语言」。代码里已经预留了位置（见下）。 |

## 四、加一门语言的成本

提示词里只加一个分支就够了：

```
backend/app/prompts.py
def build_messages(target, *, kind="word", language="en", ...):
    if language != "en":
        raise NotImplementedError(f"暂时只支持英语，收到 {language!r}")
```

数据库、流水线、界面、间隔重复调度**都不需要动** —— 它们处理的是
「例句 + 场景 + 通道」，和具体语言无关。要加日语，需要做的是：

1. `prompts.py` 里加一个分支和一条语言特定的指令（比如日语要额外给假名读音）；
2. TTS 音色列表加日语选项；
3. 界面上的文案不用改。

**这是一个刻意的架构选择**：语言只存在于提示词和音色表里，
不出现在数据模型里。

## 五、这套东西**不能**替代什么

避免误以为它做了什么它没做的事：

- **它不产生语料。** 例句是模型生成的，质量取决于模型。用弱模型会得到
  平淡甚至不地道的句子 —— 这不是程序能修的，换模型比改代码有效。
- **它不保证不遗忘。** 间隔重复降低遗忘速度，不消除遗忘。原文也说了
  「遗忘对学习很重要」，所以这不是缺陷。
- **它不衡量你的水平。** 评分是你自己打的（「没想起来 / 吃力 / 正常 / 秒答」），
  程序不判断对不对 —— 打字卡除外，那个是逐词比对，但比对的是**字面**，不是**发音**。
- **还没有验证过真人长期使用效果。** 代码逻辑对着理论写了，
  但「照着练三个月会怎样」没有任何数据支持，也不该被声称。
